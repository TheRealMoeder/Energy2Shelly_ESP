# AGENTS.md

PlatformIO firmware (Arduino framework) that emulates a Shelly Pro 3EM on ESP8266/ESP32 (C3/S3). Input power/energy data is read from one of several sources (MQTT, SMA multicast, SHRDZM UDP, generic HTTP, SUNSPEC Modbus TCP, TibberPulse) and served via Shelly-compatible HTTP/JSON-RPC endpoints so a solar inverter / battery (Hoymiles, Growatt, Marstek) sees a virtual Shelly 3EM.

## Build & verify

- There are **no tests**. Building is the only verification: `pio run` builds all 4 envs (`esp32`, `esp8266`, `esp32-s3`, `esp32-c3`). Use `pio run -e <env>` for one (e.g. `-e esp8266`, the tightest target). CI runs `pio run`.
- Version injection is a build-time codegen step: `build_flags = !python get_version.py` emits `-D VERSION_BUILD="..."` from `git describe --tags --always`. The build therefore **requires a git checkout with commits/tags** — it will fail or produce a broken version string outside git. `<project>/get_version.py` runs from the project root.
- Debug output goes to serial at **115200** baud and the `/console` WebSocket page. The `DEBUG` macro in `src/config/Configuration.h` toggles all `DEBUG_SERIAL` logging (false compiles it out entirely).
- Fast validation loop: `pio run -e esp8266 -e esp32-c3` after parser/config/logic changes; together these cover the tightest target (esp8266) and the C3 (smallest ESP32 flash env) and are much faster than the 4-env build. CI still runs `pio run` for all 4.

## Architecture

- `src/parsers/` — one module per input source (`MqttParser`, `SmaParser`, `ShrdzmParser`, `HttpParser`, `SunspecParser`, `TibberPulseParser`). Each produces power/energy values via `src/data/DataProcessing.(h/cpp)` (`setPowerData`, `setEnergyData`), which normalizes into the shared state used by the RPC layer.
- `src/rpc/` — generates the Shelly 3EM JSON-RPC responses served under `/rpc/*` (both GET endpoints and a POST JSON-RPC body at `/rpc`).
- `src/config/Configuration.(h/cpp)` — all settings are **fixed-size global `char` arrays** persisted via Preferences (NVS on ESP32, `vshymanskyy/Preferences` lib on ESP8266). WiFiManager's captive portal supplies the values.
- `src/web/html_home.h` — the entire web UI lives here as **C string constants in PROGMEM**, streamed to the client in fragments (`memcpy_P`). There are no standalone HTML files.
- `src/main.cpp` — wiring/entrypoint: registers all HTTP endpoints and per-source setup + periodic polling blocks (`worker_loop`).

### Adding a new data source
Wire it in four places, mirroring an existing source (e.g. HTTP):
1. New `src/parsers/XxxParser.cpp` + declaration in `src/parsers/Parsers.h`.
2. New `dataXXX` bool flag in `Configuration.h` and set it from `input_type` in `Configuration.cpp` (default fallback is MQTT).
3. Setup block (open socket/client) and loop block (poll/parse) in `main.cpp` — note `period` (query interval ms) is shared between HTTP/SUNSPEC/TibberPulse.
4. WiFiManager parameters (with exact fixed buffer sizes) in `Configuration.cpp`.

## Platform quirks

- ESP8266 is the memory-critical target: global static buffers and PROGMEM-streamed HTML are deliberate (avoid heap fragmentation). Keep new code in that style; don't allocate big stack/heap Strings in hot paths.
- `NOWIFIMANAGERASYNC` is only defined for ESP32 envs (compiled-in library behavior differs). ESP8266 additionally relies on the `#define WEBSERVER_H "fix WifiManager conflict"` in `Configuration.h` — do not remove it.
- ESP32-S3/C3 need `ARDUINO_USB_CDC_ON_BOOT=1` for serial over USB.
- ESP8266 partition scheme is the default for `nodemcuv2`; ESP32 envs use `min_spiffs.csv` (little flash free — keep firmware+HTML small).
- WebSocket / endpoint registration uses **ESPAsyncWebServer** (`AsyncWebServerRequest`); all the `server.on(...)` routes are in `main.cpp`.

## CI & release

- Workflow `.github/workflows/main.yml`: builds all envs, then merges the ESP32-family flash images (`esptool.py merge_bin`) and copies firmware into `.github/pages/*.bin` (the browser webflasher) + uploads artifacts.
- Release (GitHub release + Pages deploy) happens **only on git tag pushes** (`github.ref_type == 'tag'`). Versioning is tag-driven (`v0.x`); `git describe` output ends up in the binary. CI skips runs for `**.md`, `/doc/**`, `/screenshots/**`.
- The webflasher manifest is `.github/pages/manifest.json` (merged bins at offset 0); the merged flash is generated by CI, never committed by hand.

## Endpoints (for manual testing)

`/`, `/status`, `/console`, `/reset`, `/update`, `/rpc/EM.GetConfig|GetStatus`, `/rpc/EMData.GetStatus`, `/rpc/Shelly.*`, `/rpc/Sys.*`, `/rpc/WiFi.GetStatus`, plus POST JSON-RPC at `/rpc`. `/update` restarts into WiFiManager config portal (used for OTA via webflasher binaries from Releases).
